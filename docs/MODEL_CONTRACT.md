# 当前模型合同与已知边界

checkpoint-48来自车载第二阶段训练作业32769，从第一阶段checkpoint-252继续训练。本版本使用原生checkpoint完整参数，Qwen3-ASR-0.6B共享decoder，原生ASR输入保持；Output显式使用vehicle_tool_messages_v3工具模板。运行时保留FP32/BF16原生参数配置，加载step必须为48，逐项校验checkpoint的prompt_contract资产哈希。

权重不在GitHub。服务维护者另行提供模型目录/发布哈希与只读权限，展示电脑只使用经过认证的RPC。仓库内prompt_assets是接入所需模板，不是模型权重或完整训练数据。

输入：唯一System（固定规则＋河套身份补充＋当前23项车况）和当前用户原话。没有前轮历史。操作：最多一个control_cabin，合并参数；原CabinVehicle验证并执行，返回ok/before/state/patch；同一个call_id的role=tool回执供模型生成最终回复。无操作直接回复。Kokoro独立播报，原生模型不生成声音。

禁止不完整输出、未知工具、非法参数、重复请求和结果后再次调用。明确失败不会交给未训练过失败轨迹的模型编造成功回复。语义错误仍可能通过合法参数执行，本系统只控制模拟器。

2026-10-17的50条无历史功能抽测结果为39条符合预期、9条错误/多余操作、2条越界被执行器拦截。已知问题包括：左后窗请求扩大到两扇后窗；解锁误为开门；上一首/下一首边界错误；否定和保持请求仍调用工具；座椅加热误映射空调制热；无明确指代仍猜对象。额外状态查询曾编造“不支持单独车窗控制”的说明。不得把这个小样本比例当作泛化准确率或生产车控认证。

原工具模板和推理代码可以继续改进，但不要用程序暗中补动作/改答案来宣称模型准确率提高。原始对话、录音和详细测试产物不随展示仓库发布。
